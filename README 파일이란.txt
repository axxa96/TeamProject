Github와 로컬 파일을 연결하기 위해서 git bash를 사용하면서 튜토리얼을 따라하다가 README.md 파일에 대해 궁금해졌다.

왜 굳이 "README.md" 파일을 추가하는걸까?

-README.md 파일이란?

README.md 파일은 파일명 그대로 자기를 읽어달라는 파일이다. 그럼 이 파일을 왜 읽어야할까? 이 파일은 간단하게 말해서 제품의 사용설명서와 비슷하다.
github를 통해서 누군가가 나의 프로젝트를 다운해서 사용하기 전에 README.md 파일을 통해서 사용법이나 사용 전 알아야하는 정보를 담아 놓은 것이다.
md라는 파일 확장명은 MarkDown의 약자로 일고 쓰기 쉬운 문서 양식을 지향하기 때문에 간단한 문법만 숙지하면 누구나 쉽게 작성할 수 있다고 한다.  


-README 파일의 필요성

1) 나 자신을 위해서 
 내가 진행한 프로젝트(소프트웨어)더라도 모든 내용을 다 알 수 없기에 메모의 느낌이 있고 다시 읽어보고 수정하는 과정을 거칠 때 README 파일이 도움이 된다.

2) 유저를 위해서
소프트웨어를 오픈소스로 배포하는 경우 내 프로그램을 사람들이 쉽게 사용하게끔 할 수 있다. 앞서 말했듯이 제품의 사용설명서와 비슷하다.

3) 협업하는 사람을 위해서
같이 프로젝트를 진행하는 동료들에게 우리 프로젝트의 방향성과 목적을 담은 지침서 역할로 쓰일 수 있다.

-README 파일 문법(내가 알기 쉽게 정리)

제목은 #

줄바꿈은 엔터 2 번

구분선은 --- / ***

인덱싱은 1. 후 자동으로 기입됨

불릿은 인덱싱과 비슷한 용도로 사용되고 + /  - / * 

텍스트 강조 ** (볼드) / __ (이탈릭)  /  *** / ___(볼드 이탈릭) / ~~~(취소선)   문장 양쪽에 

인용구는 >

하이퍼링크는 <>

이미지는 REPO에 직접 추가



느낌점: README 파일에 대해서 직접 알아보기 전에는 별 중요성을 못느꼈지만 조사 후에는 README 파일은 프로젝트나 소프트웨어 배포 시 가장 중요한 파일이라는 것을 알게 되었다. 이번 조사를 통해서 README 파일이 제품의 사용설명서 역할을 할 뿐만이 아니라 협업 시 팀원들과 활동하는데 지침서가 된다는 역할을 할 수 있다는 점을 알게 되어 README 파일의 중요성을 확인하는 계기가 되었다.
